# 知径系统级多形式交付

用户在 2026-09-08 明确要求补齐知径整个系统，不是继续增加单篇 Demo 的控件。本轮完成态：正式问卷与个人 Skill → 用户提供真实文章 → 来源核对后的完整学习内容 → 图文、逐章图解、全文关系、独立听读、讲解视频、可选互动与复习 → 保存、续看、补充形式、下载。

## 执行边界

- 正式站点 `/zhijing/` 是交付入口；历史 Demo 保留，不再作为通用能力的完成证据。
- 多形式共用一份来源与知识结构，但音频用不依赖画面的独立讲稿，不把视频音轨冒充音频适配。
- 结构分析、完整编排与核对、互动编排及核对各有单独职责；只修改应用内部提示词，不装备或修改用户全局 Skill。
- 旧作品不丢失，完成的新作品可补充音视频；失败保留成功内容，只重试缺失部分。
- 学习位置、笔记与可选练习保存在私有服务端；不根据行为暗中改写个人 Skill。
- 4 核 8G 服务器继续串行制作，沿用现有模型、配音和权限；不新增收费供应商、公开原文或变更其他服务。
- “学习效果更好”、无限并发、商业收费、实名账号与异地备份不是本轮可宣称完成的事项。

## 验证

兼容旧数据、来源约束、完整性、权限隔离、状态保存与恢复、补充生成及局部失败重试；真实模型处理用户给出的文章及另一篇不同主题文章。模型内容差异不当作有效性实验证据。发布使用新版本目录、数据库一致性快照、旧版本回退，保留历史静态案例及私有媒体。

当前为执行计划，尚未完成发布；最终证据另记在本文末尾。

## 实现与验收中解决的问题

- 正式生成返回 `schemaVersion: 2`，所有新作品使用同一个主站学习页，历史 Demo 保留为独立历史作品，不再混用为通用系统的验证。
- 新增章节结论、成立条件、复习卡、独立听读讲稿；完整核心概念覆盖检查。长文可编排至 12 章，而非为固定 10 章上限遗漏内容。
- 真实长文测试发现模型会抄错引句或猜错片段编号。改为程序生成逐字原文片段目录，模型只选片段编号，程序核对并直接提取原文；无效编号仍不能交付。结构错误提供具体缺失项，最多自动修正一次，不用假结果兜底。
- 所有模型调用带当前日期，并明确区分原文事实陈述、作者推演、平台教学虚构。人工抽查发现过“未核验被误写成未发生”的问题，因此加强边界核对；这些工程检查不等于全面事实认证。
- 多媒体分两条制作：`audio.m4a` 是视频讲解音轨，`listen.m4a` 是独立听读。已完成文件保留，未完成文件使用临时名称，验证成功再交付。
- 私有 `lesson_state` 表保存章节、两种播放时间、卡片与推演选择、笔记；参数裁剪与账户权限检查。原作品、个人 Skill、学习行为分别存储，不暗中改写长期学法。
- 学习库增加标题搜索和 24 条分页，旧作品仍可读，重新生成做独立副本；补充音视频不重做正文，重复请求已完成媒体不重复扣生成次数。
- 离线 HTML、Markdown 和 JSON 提供学习内容、原文依据与笔记；媒体和逐章 SVG 独立下载。
- 浏览器点击和截图测试脚本已同步新入口，但本轮没有执行浏览器交互验收；本轮使用组件服务端渲染、真实 HTTP、数据库重启、文件校验和媒体验证。
