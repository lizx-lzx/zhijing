# 运行、部署与完整打包

本文描述 GitHub 当前交付方式；`01`—`20` 号文档保留各阶段决策和历史验收，不以旧记录替代当前状态。

## 本地运行

建议 macOS / Linux 或 Windows WSL，Node.js 24。仅浏览预置案例不需要重新配音或渲染视频；制作新媒体还需要 FFmpeg / ffprobe、Playwright Chromium 与中文字体。

在项目根目录：

```sh
npm ci
npm run demo:install
cp .env.example .env.zhijing
npm run demo:build
```

然后分别打开两个终端：

```sh
# 终端一：后端，默认 127.0.0.1:4330
npm run api
```

```sh
# 终端二：前端
npm run dev:demo
```

打开 <http://localhost:3000/zhijing/?start=welcome>。跳过问卷直接浏览预置作品：<http://localhost:3000/zhijing/demo/zhihu-window-20260908/?experience=demo&mode=video>。

`demo:build` 只组装仓库里的既有资料，不调用模型、不重新合成媒体。AI 学法设计和小猫对话仍需要有效模型配置；未配置模型时，问卷最后会显示错误，可选「先用基础规则继续，之后可以再调整」。不要把这条降级路径当成真实 AI 设计已经成功。

在知径网页内，Mac 使用 `Option + Shift + R`，Windows 使用 `Alt + Shift + R`，可直接打开问卷第 1 题反复录制。固定入口为 `?start=questionnaire`，使用默认答案；在此页面刷新仍会打开问卷，不删除作品，也不自动覆盖已保存偏好。

`?start=welcome` 仍可从欢迎页开始；点击「找到我的学法」后，地址会保留问卷入口。「读法笺」内的「重新做问卷」使用 `?start=preferences`，读取已有答案供修改，与录制用的全新问卷区分。普通首页不带这些参数时，已完成问卷的用户仍直接进入书房。

## 哪些东西包含在仓库里

- 主站 UI、问卷、学习 Skill 设计提示词、AI 小猫、后端接口、SQLite schema、测试和部署脚本。
- 六形式文章案例的数据、完整原文、讲稿、时间轴、图解与成片。
- 动画 HTML/CSS/JS、冻结动效引擎、GSAP、视频封面和成片。构建不再读取其他项目的绝对路径。
- 旧数学试作保留源码与媒体用于历史复现，当前入口仍以知乎文章为主。旧版可用 `npm run build --prefix experiments/openmaic-preview` 单独构建。
- 原始项目 Git 历史、产品决策文档及第三方来源说明。

构建出的 `public/demo/zhihu-window-20260908/`、`public/demo/zhihu-motion-20260910/` 和 `dist/` 不重复提交；其源数据与媒体已纳入仓库，按命令可重建。

不会上传 `.env.zhijing`、供应商 Key、恢复码、私人音色参考、SQLite 数据、用户作品和会话、测试账号结果、node_modules、渲染帧缓存。依赖通过 lockfile 安装。若私人数据出现在新路径，不能仅依赖 `.gitignore`，提交前仍须按文件检查。

## 部署

线上主入口是 <https://app.chainvalley.top/zhijing/>，使用用户自有服务器，不使用 GitHub Pages。GitHub 存放项目，不替代当前网站后端。

```sh
npm run build:complete
```

已提供 `deploy/zhijing-learning.service`、`deploy/zhijing-api.service` 和 `deploy/zhijing-location.conf`；安装到新机器前修改用户名、工作目录、Node 路径、域名、端口及私有环境文件路径，不能直接照搬生产机器路径。

前端进程为 `zhijing-learning.service`（4329），API 为 `zhijing-api.service`（4330）；SQLite、私有媒体和环境文件位于 release 目录之外。

- 纯 UI 发布：`deploy/activate-ui.sh`，必须传入新目录和精确的旧目录；仅重启前端，失败恢复旧前端。
- 后端 / 依赖变更：使用 `deploy/activate-system.sh`，先检查队列并创建一致性快照；不要套用首次迁移脚本 `activate.sh`。
- GitHub 上传不会自动触发线上部署。本轮只整理源码仓库，不更改线上数据或供应商配置。

## 验证边界

`npm run typecheck` 检查类型；`npm run test:unit` 运行单元和接口测试；案例测试为 `npm test --prefix experiments/openmaic-preview`。部分媒体与原文专项测试依赖显式传入材料，跳过不代表通过。

现存 ESLint 历史问题使 `npm test` 不保证全绿；没有添加虚假的 CI 通过标识。真实模型验收脚本会产生用量，不能为了查看仓库自动运行。构建通过不代表任意文章生成质量或学习效果已经保证。
