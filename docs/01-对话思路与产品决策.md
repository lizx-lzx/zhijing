# 知径：对话思路与产品决策

> 状态：当前项目决策记录  
> 日期：2026-08-29  
> 用途：还原“知径”从一个模糊想法逐步变成产品原型的思考路径。本文不是逐字聊天记录，而是把真正改变了产品方向的判断、纠正和取舍保留下来。

## 1. 最初的想法：不是摘要，而是帮助人理解

最开始的设想很直接：用户给出一篇知乎文章，平台把文章重新整理成更容易学习的形式。候选形式包括文字、图片、幻灯片、HTML、音频和视频。

但讨论很快发现，如果产品只做“文章转格式”，它和普通的 AI 摘要、视频生成器或内容转换器没有本质区别。真正想解决的问题不是让内容换一个壳，而是：

> 同一篇内容，能不能根据不同人的目标、基础、进入方式和当下状态，重新组织成不同的理解路径？

因此产品核心从“内容格式转换”变成了“个性化学习编排”。

```text
原始内容
× 用户的个人学习 Skill
× 本次学习目标与时间
→ 学习配方
→ 一件可以直接开始的学习作品
```

## 2. 从个人工具扩大成平台

第二个关键变化是从“做给自己用”扩大为“别人也能使用的平台”。

平台不能只记住一个开发者的偏好，而需要先了解每位用户，再生成一套属于他的学习规则。用户以后输入新的内容时，系统都能调用这套规则进行编排。

这形成了三层概念：

1. **平台学习基础**：学习科学、内容分析、认知负荷、来源边界和教学策略，是所有用户共享的底层原则。
2. **个人学习 Skill**：由问卷、微型体验和后续反馈形成的用户可见规则，不是后台不可解释的画像标签。
3. **本次学习配方**：结合当前文章、当前目标、可用时间和个人 Skill，临时生成的一次学习安排。

其中最重要的一次澄清是：问卷生成的不是一份好看的“性格报告”，而是 AI 真正可以执行、用户也可以查看和修改的学习 Skill。

## 3. 学习方式被打开，但没有被做成固定类型

讨论最初提到了视觉学习、听觉学习和互动学习。随后又继续打开了范围：

- 有人通过问题和逻辑进入；
- 有人需要故事、情绪和真实情境；
- 有人先看整体关系，再进入细节；
- 有人习惯在同一内容中同时看到时间、空间、因果和角色等多个维度；
- 有人愿意边学边回答，有人不希望频繁被打断；
- 有人喜欢视频或音频，但这不等于任何内容都应该做成视频或音频。

这一步保留了用户对“学习不只有理性路径”的重要判断，同时也增加了证据边界：平台不能把人固定诊断成“视觉型”“听觉型”或“情绪型”。媒介偏好可以影响进入意愿，却不能单独证明学习效果。

最后采用的适配变量更接近真实学习过程：

- 本次想达到什么结果；
- 对主题已经知道多少；
- 内容本身是概念、关系、步骤、案例还是争议；
- 从问题、案例、故事、定义还是全局地图进入；
- 需要什么深度、节奏和支架；
- 当前设备、时间和无障碍条件；
- 对文字、图解、视频、音频和互动的偏好；
- 真实回答、复述、应用和反馈表现。

年龄被保留下来，但只用于调整语言、案例、信息密度和交互方式，不能用来判断能力。

## 4. 产品边界怎样一步步收紧

讨论中出现过学习库、学习记录、长期 Skill 演化、间隔复习、社交和多平台接入等想法。最终没有把它们塞进第一版，而是确定了以下顺序：

1. 先做独立学习网站；
2. 第一内容来源只做知乎公开知识类文章；
3. 第一批主要面向 22—35 岁中文成人自主学习者，同时问卷允许更广的成年人使用；
4. 先验证“一篇文章完成一次学习”的闭环；
5. 学习库、长期记录、复习和其他平台接入等核心闭环成立后再做。

这不是否定后续平台能力，而是避免尚未证明一次学习是否成立时，就先建设一个庞大的学习管理系统。

## 5. 为什么最终保留了简短问卷

产品目标之一是减少决策负担。讨论过是否可以完全不问用户，直接让 AI 推断；最终决定仍然保留一个简短问卷，原因是冷启动阶段系统还没有真实行为证据。

问卷遵循四个原则：

- 默认只做一次，回访用户直接进入工作台；
- 问用户容易判断的具体场景，不要求理解教育学术语；
- 结果只是初稿，用户可以重新适配；
- 每篇文章开始前只补充“本次目标”和“现在有多少时间”等少量动态条件。

前期研究候选曾提出 8 个维度。当前 Demo 为了降低首次体验负担，实际实现为 6 题：年龄、目标、陌生主题入口、媒介入口、互动程度和退出诱因，再加一次 Style 微型体验。深度、节奏和情绪比例暂时没有作为独立题目。

## 6. 为什么问卷后面还有一次 Style 体验

只问“你喜欢图还是故事”，得到的是自我描述，不一定等于实际理解。因此流程增加了一个很短的对照体验：

1. 用关系图和情境故事解释同一个“公地困境”概念；
2. 用户选择更容易进入的一种；
3. 再回答一个理解问题；
4. 系统把偏好和结果一起写进个人 Skill 初稿。

这里的目的不是考试，也不是一次体验就给用户定型，而是明确区分“我喜欢这种形式”和“这种形式确实帮助我理解了关系”。

## 7. 最终形成的首次使用流程

```text
进入首页
→ 完成一次简短问卷
→ 完成一次 Style 微型体验
→ 查看并确认个人学习 Skill 初稿
→ 进入工作台
→ 粘贴知乎文章链接
→ 选择或接受本次学习目标与时间
→ 系统推荐学习配方
→ 生成并进入个性化学习作品
→ 可选切换解释方式、回答问题或完成学习
```

回访用户的理想路径更短：

```text
进入工作台
→ 粘贴链接
→ 接受推荐
→ 开始学习
```

## 8. “学习配方”最后被定义成什么

学习配方不是选择一个媒体按钮，也不是永久人格。它至少会改变以下部分：

- 内容从哪里开始；
- 知识出现的顺序；
- 概念切分的颗粒度；
- 使用定义、类比、案例、故事、关系图还是推演；
- 用户在什么位置参与；
- 哪些内容展开、哪些压缩；
- 一次学习怎样收束。

视频、音频、图片和互动 HTML 都是可用的表达器，但只有在它们能改变理解路径时才应该出现。最终输出应该是一件连续的学习作品，而不是摘要、图片、问题和卡片的机械拼盘。

## 9. 对话中的关键纠偏

| 对话中的纠正 | 它改变了什么 |
|---|---|
| 不要只讨论固定的视觉、听觉类型 | 改为多维、动态、可验证的学习条件 |
| 学习也可以通过情绪、故事和多维关系进入 | 保留体验与情境，但要求服务于理解目标 |
| 尽量减少用户决策负担 | 采用一次性短问卷、系统推荐和渐进展开 |
| 先做问卷，再生成学习 Skill | 首次入口从文章输入改为先完成个人建档 |
| 生成的不是隐藏画像，而是用户自己的 Skill | Skill 结果必须可见、可解释、可重新适配 |
| 先做网站，先接知乎 | 暂停多平台和长期系统扩张 |
| 先把前期学习部分做好 | 学习库、复习和长期记录延后 |
| ReactBits 可以优化，但页面不要被效果淹没 | 动效只表达学习路径，不做组件陈列 |
| 很多小字没有必要，遵循奥卡姆剃刀 | 删除不改变下一步判断的信息碎屑 |

## 10. 视觉和交互思路

最终界面选择了偏纸张感的浅底色、深墨色文字、靛蓝主色，以及少量琥珀和绿色辅助。目标不是做成教育机构后台，也不是做成炫技的 AI 工具，而是让它更像一张正在为用户展开的学习地图。

ReactBits 只承担两类有意义的动态表达：

- 首页围绕个人 Skill 卡片移动的学习路径标签；
- 关键标题和说明的渐进出现。

后续又做了一轮减法，删除品牌副标题、时间承诺、重复信任说明、版本碎片、问卷题号和选项解释小字。留下的内容只回答三个问题：这是什么、为什么值得开始、下一步按哪里。

## 11. 当前共同结论

知径不是“根据学习类型匹配一种媒体”的平台，而是一个个性化学习编译器：

> 它先形成用户可见的个人学习 Skill，再把原始内容、个人 Skill 和本次条件组合起来，生成一条适合此刻这个人的理解路径。

当前原型已经把这一产品逻辑完整演示出来，但还没有证明真实学习效果，也没有接入知乎正文和 AI 生成。下一阶段的核心不是继续添加页面，而是让真实文章真正经过来源可追溯的解析、分析、编排和生成链路。
