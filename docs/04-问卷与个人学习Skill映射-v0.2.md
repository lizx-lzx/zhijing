# 知径：问卷与个人学习 Skill 映射 v0.2

> 状态：问卷候选已接入本地网页，尚未作为个人 Skill 正本载入，也尚未经过真实用户效果验证  
> 日期：2026-08-29

## 1. 这份问卷负责什么

问卷只负责冷启动：用用户容易回答的具体选择，生成一份 AI 可执行、用户可见并可修改的个人学习 Skill 初稿。

它不负责诊断视觉型、听觉型、情绪型等固定人格，也不承诺一次问卷能够证明哪种形式学习效果最好。用户选择表达的是默认入口、愿意持续的方式、理解支架和明确限制；微型体验另外记录一次低置信度的行为证据。

```text
6 道单选题
+ 1 次同概念双版本体验
+ 1 道理解题
→ PersonalLearningSkill v2
```

完成标准不是“生成一段像测评报告的描述”，而是每个答案都至少改变一条生成规则，并且矛盾答案能够得到明确处理。

## 2. 正式问卷

### Q1 年龄阶段

**你现在处于哪个年龄阶段？**

- 18—21 岁
- 22—29 岁
- 30—39 岁
- 40 岁以上
- 暂不透露

年龄只允许改变语言语境、案例假设和信息密度，不得用于推断智力、能力上限或固定学习方式。18—21 岁不默认具备长期职业经验；其余成年人统一使用清晰的成人表达，避免根据年龄制造刻板差异。

### Q2 默认学习结果

**读完一篇重要内容后，你最希望得到什么？**

- 快速看懂：先交付问题、结论和必要依据，压缩可选背景
- 形成结构：先给知识地图，按前置、因果、对比和例证展开
- 记住重点：控制关键点数量，提供组块、线索和可选回忆
- 学会应用：补充真实用法、判断步骤和迁移情境
- 讲给别人：形成可转述的观点链和可选讲述提纲

这是长期默认目标，不表示所有文章都必须采用同一个目标。第一版不再逐篇强制询问，学习作品内提供轻量切换入口即可。

### Q3 默认入口与首选载体

**面对陌生内容，怎样开始最容易让你进入状态？**

- 先看一张全局图：关系图先行，再进入局部
- 先听一个故事或案例：情境先行，随后收束为概念与关系
- 先看一段短视频：存在时间、空间、因果或操作变化时优先视频
- 先抛出一个核心问题：后续信息围绕问题逐步展开
- 先读一段清晰文字：结论、定义和边界先行
- 交给系统判断：根据内容类型选择入口

这里把“从哪里进入”和“什么载体愿意开始”合并为一次选择，减少一道题。短视频是优先级而不是硬命令：内容没有动态表达价值时，系统应选择更轻、更清楚的图文形式。

### Q4 卡住时的理解支架

**遇到难懂的地方，哪种帮助对你最有用？**

- 换成大白话
- 给一个熟悉的类比
- 补一个真实案例
- 画出因果或关系
- 拆成具体步骤
- 看反例和常见误区

这一题决定第二解释路径。平台不能只把原文换一种措辞重复，而要真正改变信息组织方式。

### Q5 互动程度

**学习过程中，你希望平台怎样与你互动？**

- 直接完整讲清楚
- 最后给我一个可选练习
- 中间留一个思考点
- 让我参与推演

无论用户选择哪项，第一件学习作品都一次性完整生成；互动只能是作品内部可跳过的学习动作，不能强迫用户等待回答才能看到后文。

### Q6 优先避免项

**哪种情况最容易让你中途退出？**

- 连续大段文字
- 信息密度太高
- 解释节奏太慢
- 内容过度抽象
- 频繁被提问
- 形式太花哨

只选最明显的一项。避免项是硬于普通偏好的生成限制，但不能损害来源完整性和核心逻辑。

## 3. 微型体验

平台用关系图与情境故事解释同一个“公地困境”概念，用户先选择更愿意继续的一种，再回答一道理解题。

两种证据必须分开保存：

- 选择哪一种，只说明当前更愿意从哪里进入；
- 理解题是否答对，只提供一次低置信度的理解证据；
- 答对不把偏好升级成固定人格；
- 答错不否定用户偏好，而是在生成时增加第二种解释支架。

## 4. 个人学习 Skill 的输出

网页当前生成并保存以下结构：

```ts
type PersonalLearningSkill = {
  version: 2;
  headline: string;
  summary: string;
  labels: {
    age: string;
    goal: string;
    entry: string;
    support: string;
    interaction: string;
    avoid: string;
  };
  rules: Array<{
    id: string;
    label: string;
    instruction: string;
    evidence: "问卷回答" | "微型体验" | "平台底线";
  }>;
  adjustments: string[];
};
```

`labels` 用于向用户解释，`rules` 交给后续学习配方使用，`adjustments` 保存系统如何处理矛盾答案。问卷产生的整个 Skill 都只能叫“初稿”，不能写成已经验证的学习能力结论。

## 5. 规则优先级

出现冲突时按以下顺序处理：

```text
来源真实性、安全与无障碍
> 用户明确避免项
> 内容本身的表达需求
> 本次学习目标
> 个人默认入口和支架
> 单次微型体验
> 生成成本与装饰效果
```

这意味着：喜欢视频不等于所有内容都生成视频；喜欢故事不允许把原文观点编造成故事事实；讨厌长文也不能删除决定结论成立的必要依据。

## 6. 当前明确处理的矛盾

| 用户答案 | 系统处理 |
|---|---|
| 想参与推演，同时最怕频繁提问 | 降为文末一次可选练习 |
| 喜欢视频，同时最怕形式花哨 | 保留视频入口，只使用表达关系所需的克制动画 |
| 喜欢文字，同时最怕大段文字 | 使用短段落，并用结构图承担全局关系 |
| 问卷喜欢故事，微型体验更喜欢关系图 | 故事负责进入，关系图负责固定核心结构 |
| 问卷喜欢图或视频，微型体验更喜欢故事 | 原入口保留，关键概念补一个短情境 |
| 微型理解题答错 | 不给用户定型，生成时补充第二解释路径 |

## 7. 不再逐篇追问熟悉度的处理

一次性问卷无法知道用户是否熟悉未来每个主题。为了不把负担重新推回用户，第一版不强制追问，而是在同一件学习作品里分层：

```text
20 秒概览
→ 必要前置知识
→ 核心解释
→ 可展开的深入内容
```

熟悉用户可以直接跳过前置，陌生用户不会断层。以后有了真实学习记录，可以提出 Skill 更新建议，但只有用户确认后才改写长期规则。

## 8. 仍然需要真实用户验证的部分

当前版本已经通过逻辑映射检查，但以下问题不能靠设计者自证：

- 六题是否真的能在两分钟内完成；
- 用户能否理解“默认入口”而不误以为平台给自己定型；
- 两种不同答卷是否生成了肉眼可见、学习路径不同的作品；
- 微型体验是否过长或像考试；
- 用户是否认可系统对矛盾答案的处理。

在这些问题获得真实证据之前，本版本是可运行候选，不是已经证明有效的正式量表。
