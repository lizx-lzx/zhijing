# 知径完整产品实施与验收

2026-09-06，用户授权直接推进完整产品；沿用自有 4 核 8G 服务器，不再部署 Sites。

## 本次交付边界

一次建档 → 可解释、可编辑的个人学习 Skill → 知乎公开链接或正文 → 来源锚定的 AI 学习作品 → 图文、网页动画、配音、MP4 → 私人学习库与恢复。

短问卷按三组组织；主载体与讲解方式独立，允许补充载体、多项避免项、交给系统、随时返回。第一次完整交付不以答题为门槛，练习为可选内容。年龄不用于能力推断；系统不得未经用户确认修改长期 Skill。

## 实现路线

1. 保留已有候选到 Git，再将前端状态机拆分为问卷、Skill、工作台、学习作品等组件。
2. 单独的 Node API + SQLite 存储用户、会话、来源、Skill 版本、生成任务、作品及反馈。访客优先，恢复码支持跨设备，不引入强制注册。
3. 将设计 Skill、内容结构分析、个性化编排、独立核对分别作为应用内提示词模块，不安装或修改用户全局 Skills。
4. 模型调用只在服务端进行。链接读取受域名、响应大小和超时限制，访问受限时明确要求提供正文，不伪装成功。
5. 使用同一份带来源编号的内容模型生成多种表现形式；网页与视频共用章节、图解和时间线，复用现有流水线的配音接口及 FFmpeg 合成方式。
6. 串行媒体队列、任务持久化、可重试、每用户及全局限额，避免小服务器被并发渲染或公开接口滥用。
7. 构建、数据隔离、恢复、恶意输入、失败重试、真实模型差异和真实音视频验收后，再发布独立版本，保留上一版本可回退。

## 验收

- 不同答卷产生有依据且可编辑的规则；相同文章在故事/分析等规则下得到不同的入口、顺序与支架。
- 一次建档保存后刷新仍可使用；不同会话数据互不可见；恢复码能恢复本人作品。
- 正文改变后生成内容确实改变；每个章节能返回原文段落；例子明确区分原文与虚构。
- 音频、视频是当前内容的真实产物，能播放、下载，字幕与章节时间一致，不以旧样片代替。
- 失败、超时、限流、页面刷新与服务重启有可理解的处理；没有误导性的成功状态。
- 无密钥进入前端、Git 或用户响应；无任意地址抓取、任意脚本执行、跨用户读取。
- 公网主流程与健康检查通过。学习效果提升仍需要真实用户研究，工程验收不冒充科学有效性验证。

## 当前边界与运维

- 访客会话与恢复码不是实名账号系统；恢复码由用户私下保存，丢失 Cookie 和恢复码后无法自行找回。恢复码不等于数据备份，当前未配置异地备份。
- 学习库界面显示最近 60 份作品，底层不因此删除较早的数据；更大规模的分页检索留待扩展。
- 知乎是否允许读取取决于来源站点；正文输入可用，不做访问限制绕过。
- 生成与独立核对仍由 AI 执行，只核对给定材料，并没有替用户验证文章中的外部事实。学习效果、长期记忆、真实用户偏好匹配效果仍需用户研究。
- 字幕按章节配音时长进行句子级近似分配，不是 ASR 逐字强制对齐。视频是结构化图解动画，不承诺电影级人物场景视频。
- 串行视频队列、每日限额、磁盘余量检查、15 分钟成片上限、30 分钟渲染上限、2G 内存与 2 核 CPU 配额均已配置。未做大规模并发压测；这是小规模可用发布，不宣称无限容量或免运维商用服务。
- 仅变更本项目版本目录、私有目录、systemd API 服务和 Nginx 的知径 location；没有调整其他网站、代理、TLS、全局 Skills 或原自媒体流水线配置。
